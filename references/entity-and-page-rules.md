# 实体与建页规则

本文件按需读取：当你要创建、升级、合并或删除人物、组织、公司、奖项/竞赛页面时使用。

## 页面类型

| 类型 | 目录 | 说明 |
|---|---|---|
| 高校 | `wiki/universities/` | 每所重点高校一页，面向投资与高校合作提供团队、技术、公司进展与合作平台概览；重点表可直链有明确关联的实体，完整组织目录按一级组织维护 |
| 人物 | `wiki/people/` | 教授、学生、校友、创业者、产业研究员统一放入人物页 |
| 组织 | `wiki/orgs/` | 院系、研究院、实验室、课题组统一放入组织页 |
| 奖项/竞赛 | `wiki/awards/` | 长期覆盖获奖人、团队、项目、指导教师和公司化线索 |
| 公司/创业项目 | `wiki/companies/` | 有明确高校关联和商业信号的公司 |
| 索引/专题 | `wiki/maps/` | 观察池、已创业地图、方向地图、奖项入口 |
| 问题 | `wiki/questions/` | 冲突、不确定性、待验证问题 |

## 高校页：投资与合作概览

- 读者为专业投资和高校合作BD人员。按“重点团队与技术、创业与商业进展、合作平台与科研负责人”组织事实表，必要时补充早期人才与项目来源。开篇仅列重点领域和资料核对日期，不写研究画像、故事、阅读方法或推荐话术。
- 主表用具名负责人/团队、具体技术或产品、确切高校关系、已披露里程碑回答业务问题；缺乏证据的学校缩减栏目，不为凑版面填“有潜力”“适合关注”等判断。
- 重点表允许直接链接已有的人物、公司和任意层级研究组织，前提是存在已证实的任职、师承、创业、孵化或合作关系。链接文字可使用页内无歧义的简称，目标使用实体当前路径。不创建完整平行名册，不因背景比较增加图谱关系。
- 完整院系与组织目录仍按 `tier: 1` 维护，可折叠后置；下级组织的完整列表仍由其父组织维护。精选团队可跨层直达，不改写 `tier` / `parent` 或推定行政关系。
- 融资、产品与合作写披露时点及来源口径；未知币种、当前经营或关键角色就地标注。教师创业、校友创业、正式孵化、产业任职、论文合作分别记录，不推定学校持股或技术授权。
- 科研负责人不自动视为商务联系人；既有合作不表示当前有对外合作意愿。不得编造可投状态、BD对接窗口、技术成熟度评分或合作需求。
- 原文核验仍按来源规则执行；高校页的 Sources、Raw、Updated 证据块在标题后使用引用块内的折叠区，默认收起，兼容现有证据校验器；完整目录后置。只列影响投资或合作判断的具体待核项，避免重复通用免责声明。
- 同步维护 `templates/tmpl-university.md` 与高校索引摘要；不自动发布网站或扩大高校覆盖。

## 建页阈值

| 对象 | 建页条件 |
|---|---|
| 高校 | 已确定纳入覆盖范围；即使 orgs/awards 尚未建页，也可先建覆盖声明页并标 `coverage_status: planned` |
| 人物 | 已创业；或 T1/T2 高潜；或多次出现在奖项、论文、实验室、公司线索中 |
| 公司 | 有明确高校关联，且有产品、融资、客户、招聘、工商、官网等至少一个商业信号 |
| 组织 | 持续产出高潜人才、创业公司、产业合作或关键技术路线 |
| 奖项/竞赛 | 能稳定提供人才/团队线索，或与创业转化强相关 |
| 问题 | 关键事实冲突、来源互相矛盾、需要持续追踪 |

T3 线索默认不建人物页，优先放在奖项/竞赛页或对应组织页的“待补证人才与组织线索”小节。已有独立观察池且确有比较价值时可承接；不按导入批次自动建地图。

## 人物页硬门槛（≥2 条独立信号）

除职称/学籍之外，至少还能写出 **2 条独立信号**，才给这个人建人物页。合格信号包括：具名论文或代表性工作、开源项目、奖项/竞赛、公司/工商关系、专利、产业合作、指导的学生去向、公开的职业轨迹（如"某年从某机构加入"）。

不合格的"信号"：官网职称、研究方向列表、所在课题组名称、"页面未列研究方向"、由方向推断出的创业潜力。

不过门槛的人只进组织页的人员名册或待补证小节；已有观察池时可由该页承接。

这条门槛与 T0–T3 跟踪等级配合使用，但更可操作：T 分级需要主观判断"信号强不强"，而"能不能写出 2 条独立信号"可以直接验证。方向命中重点领域**不能**替代这条门槛——方向对但没有独立信号的人，页面内容会退化成职称的复述。

批量导入学院级人员名单时，另读 `college-roster-import-sop.md`。

## 跟踪等级

| 等级 | 含义 | 处理方式 |
|---|---|---|
| T0 | 已创业、已融资、已形成明确公司/产品 | 建人物页和公司页 |
| T1 | 强创业/产业化信号 | 建人物页，进入高潜观察池 |
| T2 | 有奖项、论文、开源、导师网络等可跟踪信号 | 可建人物页，也可先放在奖项页 |
| T3 | 单次名单或弱线索 | 不建人物页，留在奖项/竞赛页表格 |

## 最小字段

YAML 只放索引和筛选必要字段，不把正文事实拆成大量字段。

```yaml
type:
name:
aliases: []
domains: []
watch_tier: T2
last_verified:
confidence: single_source
tags: []
```

## 组织层级字段（tier / parent 规范化）

组织页（`wiki/orgs/`）YAML 在最小字段之外，固定使用以下扩展字段：

```yaml
org_type: department | institute | lab | group
tier: 1
parent: 清华大学
```

- `tier` 表示该组织在"高校→…→本组织"链条上的跳数：高校下属的院系/研究院（无论 `org_type` 是 department 还是 institute）一律 `tier: 1`；挂靠某个 `tier: 1` 组织的实验室/课题组/研究中心（无论官网称呼是"实验室""课题组"还是"研究中心"）一律 `tier: 2`；若某校出现更深层级（如研究院下设中心、中心下设课题组），按跳数继续加深，不要因为官网叫法不同就压缩或跳过层级。
- `parent` 必须逐字等于目标组织页 `name:` 字段的值（不得附加别名括注，如不要写"清华大学人工智能学院（CollegeAI）"，应写"清华大学人工智能学院"），使 `parent` 可以被字符串精确匹配到唯一的目标页；高校顶层用 `清华大学` 这类高校页标题，不需要该高校也建一个"org"页。
- 现实中的行政挂靠关系（例如某研究院实际挂靠某"科研院"这类纯行政机构、且该机构不满足建页条件）写在正文"基本信息"表的"所属单位"行作为说明文字，不写进 `parent` 字段——`parent` 只承载 wiki 树形导航用的父节点，行政细节和树形父节点是两回事，混用会让父链断裂。
- 组织的真实上级机构在来源中存在冲突或无法确认时（如两个名称相近的机构是否为同一实体），`parent` 按现有可确认的最上层填写，正文"所属单位"行标注"待验证"并链接到 `wiki/questions/` 下的对应问题页，不要为了让树形结构好看而把未证实的归属写成确定链接。
- 每个 `tier: 1` 组织页固定维护一个"## 下属实验室/课题组"小节（表格：实验室/课题组 | 重点方向），逐字列出所有 `parent` 指向自己的 `tier: 2` 页面；高校页的完整组织目录只维护一级组织，重点团队表可精选直链下级实体。新增或删除一个 `tier: 2` 组织时，必须同步父组织清单；若该团队被高校页精选，再同步该行，不批量复制下级名录。暂无下属实验室/课题组的 `tier: 1` 页面也保留这个小节标题，用一句话说明"目前未建页"，保持所有 `tier: 1` 页面结构一致。

## 关系处理

- 人物和组织、奖项、公司之间的关系写在正文表格中。
- 只有真实关系才使用链接：归属、导师、获奖、创办、任职、实验室源头、产业合作、融资、供应链、客户、项目公司化等。
- 单纯对比、推荐阅读、背景参照默认不链接，避免图谱噪声。
- 不为论文、专利、融资事件、新闻、任职变更建事件页；它们作为证据或表格行存在。
- 人物页应尽量填写导师、所属课题组/实验室、同门/同奖项信号：判断一个创业者在某高校的"资源身位"、进而找到背景相似的人，主要依据是人物与导师/课题组这一跳关系，而不是组织本身的行政层级深浅；组织的 `tier`/`parent` 只解决"这个组织在树上的哪个位置"，解决不了"哪些人彼此资源相近"。这条在人物页建页/升级时随手补，不对存量人物页做专项返工。


## 地图的阅读与展示门槛

- 地图必须回答跨实体比较、关系定位或名单导航中的一个具体问题；名单不完整本身不是必须建页的理由。
- 单位名册与少量候选线索由组织页承接。只有持续积累、可比较的研究或产业关系才建立独立观察池。
- 当前结论直接更新到相应行；不把新批次追加成另一份平行摘要。历史错误留修订记录或操作日志，退出当前结论。
- 抓取失败、补抓计划、建页计数、工具操作和名录空栏目不作为地图正文。方向匹配和未抓到证据不能当成潜力等级。
- 网站 Home 仅推荐已有可读内容的精选入口；原始资料、待补证队列、覆盖声明和工作记录不占首页推荐位。完善后人工重评，不自动上架。
